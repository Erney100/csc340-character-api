# csc340-character-api
CSC 340 Character REST API using Spring Boot and PostgreSQL

# Character REST API

## Project Description

The Character REST API is a Spring Boot application that allows users to create, view, update, delete, filter, and search fictional characters. The application uses a PostgreSQL database hosted on Neon and is deployed on Render.

## Technologies Used

* Java 25
* Spring Boot
* Spring Data JPA
* PostgreSQL
* Neon
* Maven
* Docker
* Render

## Character Attributes

Each character has the following attributes:

| Attribute     | Description                                 |
| ------------- | ------------------------------------------- |
| `characterId` | Unique identifier generated by the database |
| `name`        | Character's name (required)                 |
| `description` | Description of the character (required)     |
| `universe`    | The character's universe or franchise       |
| `role`        | The character's role                        |
| `species`     | The character's species                     |

The `name` and `description` fields cannot be blank.

## API Endpoints

All endpoints use the `/api/characters` base path.

| Method | Endpoint                            | Description                                                        | Expected Status                                 |
| ------ | ----------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| GET    | `/api/characters`                   | Retrieve all characters                                            | 200 OK                                          |
| GET    | `/api/characters/{id}`              | Retrieve a character by ID                                         | 200 OK; 404 if not found                        |
| POST   | `/api/characters`                   | Create a character                                                 | 201 Created; 400 for invalid input              |
| PUT    | `/api/characters/{id}`              | Update a character                                                 | 200 OK; 400 for invalid input; 404 if not found |
| DELETE | `/api/characters/{id}`              | Delete a character                                                 | 204 No Content                                  |
| GET    | `/api/characters?universe=Sanrio`   | Filter characters by universe                                      | 200 OK                                          |
| GET    | `/api/characters/search?name=hello` | Search character names, ignoring case and allowing partial matches | 200 OK                                          |

## Example POST Request

**Endpoint:** `POST /api/characters`

Request body:

```json
{
  "name": "Hello Kitty",
  "description": "A friendly character who loves making friends.",
  "universe": "Sanrio",
  "role": "Main character",
  "species": "Cat"
}
```

A successful request returns `201 Created` and the saved character.

## Example PUT Request

**Endpoint:** `PUT /api/characters/1`

Request body:

```json
{
  "name": "Hello Kitty",
  "description": "A friendly character who enjoys spending time with friends.",
  "universe": "Sanrio",
  "role": "Main character",
  "species": "Cat"
}
```

Replace `1` with the ID of the character you want to update. A successful update returns `200 OK`. A missing ID returns `404 Not Found`.

## Validation

The API rejects requests with a missing or blank `name` or `description` with `400 Bad Request` for both POST and PUT requests.

## Running Locally

1. Install Java 25.

2. Configure the `SPRING_DATASOURCE_URL` environment variable with your PostgreSQL JDBC connection string.

3. Open a terminal in the project directory.

4. Run the application using the Maven wrapper:

   **Windows:**

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

   **macOS/Linux:**

   ```bash
   ./mvnw spring-boot:run
   ```

5. Open `http://localhost:8080/api/characters` to access the API.

## Deployment

The application is deployed on Render using Docker. PostgreSQL is hosted on Neon. The database connection string is configured through Render's `SPRING_DATASOURCE_URL` environment variable and is not stored in the repository.
