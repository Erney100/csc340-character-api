About This Website

Welcome to my character gallery! This website is a collection of some of my favorite cute fictional characters.

I chose a Sanrio-inspired theme because I like the cute and colorful designs of these characters. I wanted the website to have a fun, friendly, and playful appearance.

The website uses a pink color scheme, rounded cards, and character images to create a consistent visual style. Each character has their own card with basic information about them.

This website is now a dynamic character gallery. Users can search for characters by name and universe, view character details, and add, edit, or delete characters. All character information is stored in a database instead of being hardcoded into the website.

My Design Choices

  • Pink color palette
  • Rounded character cards
  • Simple navigation
  • Easy-to-read text
  • Cute and playful appearance

How This Website Works

The frontend of this website was built using HTML, CSS, and Vanilla JavaScript. HTML creates the structure of each page, CSS controls the design and appearance, and JavaScript makes the website interactive.

The backend was developed using Java and Spring Boot. It provides a REST API that handles requests to retrieve, create, update, and delete characters. Character information is stored in a Neon PostgreSQL database.

Frontend and Backend Connection

The frontend communicates with the backend using JavaScript's Fetch API. When a user opens the gallery, JavaScript sends a GET request to the Spring Boot API to retrieve character information from the database.

When a user adds a character, the website sends a POST request. Editing a character sends a PUT request, and deleting a character sends a DELETE request. The backend processes these requests and updates the database.

Application Architecture

The application uses a layered architecture. The frontend handles the user interface, while the Spring Boot backend contains controller, service, and repository layers. The controller receives API requests, the service handles application logic, and the repository communicates with the Neon PostgreSQL database.
